# Архитектура пяти ОС и произвольных камер

Дата: 22 октября 2026. План архитектуры; полноценные клиенты ещё не собраны.

## Платформы
- Мобильные: iOS, Android.
- ПК: Windows, Linux, macOS.
- Существующий прототип SwiftUI/iOS сохраняется. Предлагаемое общее UI-ядро — Flutter/Dart для пяти ОС после проверки поддержки камер и производительности на Linux/Windows/macOS. Специфические функции оформляются как адаптеры платформ.
- Независимое ядро: Profile, Wheel, Skills, Curriculum, PracticeSession, Results, DevicePairing, CloudSync. Не связывать предметную логику с конкретной библиотекой камеры.

## Камера ПК: не только встроенная
- Источники: встроенная камера ноутбука, внешняя USB/UVC веб-камера, HDMI-камера через совместимую карту захвата (видимая ОС как видеоустройство), смартфон в режиме webcam, сетевой RTSP/IP-источник — после отдельной реализации и проверки, не объявлять поддержку любого устройства гарантированной.
- Экран выбора обнаруженных видеоустройств по понятному названию, разрешению, FPS; просмотр потока и проверка освещения/кадрирования.
- Горячее переключение, отключение, переподключение и fallback к ручному сопровождению без остановки тренировки.
- Не считать наличие нескольких камер поддержкой одновременного multi-view анализа: это отдельный исследовательский этап.
- В будущих адаптерах ПК обнаруживать камеры через OS media APIs (Windows Media Foundation, macOS AVFoundation, Linux V4L2/GStreamer/PipeWire — выбор после прототипирования); не полагаться на один общий способ для всех устройств.
- Опциональный сетевой поток требует отдельной авторизации и защиты; не открывать IP-камеру автоматически.

## Пять продуктовых разделов
Профиль (локальный без регистрации) → колесо физического состояния (12 редактируемых лучей) → каталог навыков (йога, цигун, кунг-фу, дзюдо, джиу-джитсу) → урок (демонстрация, таймер, камера) → прогресс (сессии, самочувствие, пульс по разрешению).
Возрастные шаблоны не фиксируют способности по возрасту, пользователь самостоятельно выбирает сферы.

## Два независимых протокола синхронизации
1. **История:** необязательная учётная запись, синхронизация JSON-сущностей с UUID, версиями и конфликт-резолвером, офлайн-очередь, удаление и экспорт. Без аккаунта всё локально.
2. **Живое занятие:** телефон на штативе может быть камерой, другой телефон/ПК — пультом. Pairing через одноразовый код/QR, события start/pause/step/poseSignal/stop, защищённый транспорт и timeout. По умолчанию передавать агрегированные сигналы позы, а не видео. После обрыва связи сохранять занятие и сообщать о потере наблюдения.

## Пайплайн компьютерного зрения
CameraSource → Permission → FrameNormalizer → OnDevicePoseEstimator → QualityGate (видимость, уверенность, ракурс) → TechniqueRule(для конкретного проверенного урока) → FeedbackLimiter → подсказка на экран/голос.
- Сначала оценивать только видимость и положение в кадре. Порог достоверности/точности движения необходимо калибровать на разных устройствах и телосложениях; одна 2D-камера не даёт гарантии правильности техники.
- Запись фото/видео — отдельное opt-in действие с индикацией, доступом к удалению. Видео по умолчанию не отправлять и не сохранять.
- При боли, недомогании или низком качестве обнаружения не давать команд «продолжай/углубляй позу»; давать выбор остановить упражнение.

## Интерфейс устройства камеры
`CameraDevice(id, displayName, transport, capabilities)`
`CameraSource.list() -> [CameraDevice]`
`CameraSource.start(deviceId, configuration) -> FrameStream`
`CameraSource.stop()`
`CameraSource.onDeviceLost(callback)`
`FrameStream` выдаёт фреймы только на выбранном устройстве. Backend обработки не сохраняет сырые кадры без отдельного согласия.
